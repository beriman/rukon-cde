## 2024-07-30 - Path Traversal via Unsanitized `file.originalname` in File Uploads
**Vulnerability:** User-controlled `file.originalname` was used directly to construct file system paths and S3 keys in `FilesService` and `SiteCaptureService` without proper sanitization. In Node.js, even if a string (like a timestamp or UUID) is prepended to the filename, if the original filename contains directory separators (e.g., `../`), `path.join()` will resolve the traversal, potentially overwriting arbitrary local files or bypassing S3 folder boundaries.
**Learning:** `file.originalname` from multer or similar form-data parsers must ALWAYS be treated as completely untrusted input. Prepending a prefix (e.g. `UUID-`) does not protect against path traversal when the resulting string is processed by functions that resolve paths.
**Prevention:** Always explicitly sanitize `file.originalname` before any downstream usage. Use `path.basename()` to extract only the final filename, and chain with `.replace(/[^a-zA-Z0-9.\-_]/g, '_')` to remove any remaining potentially problematic characters. Best practice is to overwrite `file.originalname` with the safe version immediately at the top of the request handler/service method so that all subsequent operations (validation, S3 metadata, DB records) inherently use the safe value.
