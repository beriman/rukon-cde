
## 2024-06-30 - [CRITICAL] Path Traversal in File Uploads and Subfolders
**Vulnerability:** Untrusted `file.originalname` and `subfolder` variables were being used to construct S3 keys and local file paths in `FilesService.upload`, `FilesService.uploadSystemFile`, and `SiteCaptureService.create` without proper sanitization. Even when `file.originalname` is appended to a generated ID like a UUID (e.g. `uuidv4() + '-' + file.originalname`), if the original name contains directory separators like `../`, it can manipulate the path and bypass intended directory bounds (Path Traversal). Also, using inline `require('path')` and `require('fs')` in Node.js core modules within a NestJS application is an anti-pattern.
**Learning:** Prepending unique strings to user-provided filenames does not secure against path traversal if the resulting string is still processed by directory-aware methods (like `path.join()`) or if S3 keys inherently define hierarchical structures. Input must be strictly sanitized explicitly. Furthermore, inline requires can lead to inconsistent or missing types and deviate from standard modern ES6 module patterns.
**Prevention:** Always use explicit ES6 module imports (`import * as path from 'path';`) at the top of files. Before appending or utilizing `file.originalname` in any path or S3 key construction, sanitize it by extracting the filename with `path.basename()` and stripping unsafe characters with a regex (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`). For parameter inputs meant to be directories (like `subfolder`), strictly validate them against traversal attempts (e.g., rejecting if they contain `..` or `\0`).
