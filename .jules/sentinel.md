## 2024-06-11 - Path Traversal via Unsanitized Original Filenames in S3 and Local Storage
**Vulnerability:** User-controlled filenames (`file.originalname`) were used directly to construct S3 keys and local file paths without adequate sanitization, presenting a path traversal risk allowing `../` sequences to overwrite unintended files or inject arbitrary key paths.
**Learning:** Even when `uuid()` or timestamps are prepended to a filename during S3 or filesystem operations, an unsanitized `file.originalname` with `../` can traverse directories up from the base storage path. Wait, the memory already explicitly notes this pattern, but it's crucial to document the specifics of where it was found in the nestjs controllers/services.
**Prevention:** Always extract the basename and replace unsafe characters using `path.basename(file.originalname).replace(/[^a-zA-Z0-9.\-_]/g, '_')` before utilizing user-provided filenames to construct storage keys or file paths, and fail securely if folder paths contain `..` or `\0`.
