## 2025-03-05 - Fix Path Traversal via Unsanitized `originalname` and `subfolder` in File Uploads
**Vulnerability:** The application was vulnerable to path traversal attacks when handling file uploads in `apps/api/src/files/files.service.ts` because it concatenated `file.originalname` directly into file paths and S3 keys without sanitization. The `uploadSystemFile` method also had a potential subfolder path traversal issue because it blindly accepted `subfolder` variable.
**Learning:** Even if the application uploads files to S3, if it falls back to local storage (or when saving `buffer` locally), concatenating `file.originalname` without extracting just the `basename` can allow files to be written to unintended directories (`../../`), leading to severe system compromise.
**Prevention:** Always sanitize the input filename from client uploads using `path.basename(file.originalname)` to remove any preceding path segments. Validate all user-supplied folder parameters, e.g., using regex `/^[a-zA-Z0-9_-]+$/` to restrict the subfolder parameter to alphanumeric characters.
