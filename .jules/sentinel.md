## 2024-05-18 - [Path Traversal via Untrusted Filenames in File Storage]
**Vulnerability:** Path traversal vulnerabilities were identified in file upload handlers (`FilesService` and `SiteCaptureService`) where untrusted `file.originalname` was used directly to construct file paths or S3 object keys (e.g. `path.join(uploadDir, file.originalname)` or appending it directly). Additionally, the `subfolder` parameter in `uploadSystemFile` was not validated against directory climbing characters (`..`).
**Learning:** Prepending a UUID or a timestamp to a user-provided filename does NOT inherently prevent path traversal if the filename still contains directory separators (`/` or `\`). When processed by `path.join()` or when creating an S3 key, these separators can still manipulate the intended storage path. Furthermore, utilizing Node.js core modules inline (`require('path')`) instead of at the file level (`import * as path from 'path';`) leads to inconsistent code organization and is considered an anti-pattern.
**Prevention:** Always explicitly sanitize user-provided filenames using `path.basename()` followed by a strict regex replacement (e.g. `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before using them in file paths or object keys. For any user-controlled folder paths, use a "fail secure" validation approach (e.g. `if (subfolder.includes('..') || subfolder.includes('\0')) throw new BadRequestException()`) rather than complex regex replacements.
