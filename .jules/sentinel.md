## 2024-06-18 - Path Traversal in S3 Key Construction via `file.originalname`
**Vulnerability:** User-provided filenames from multipart uploads (`file.originalname`) were directly appended to directory structures to create S3 object keys and local file paths. Prepending a timestamp or UUID does not stop a path traversal attack if the attacker's filename contains directory separators (e.g., `../../../malicious.txt`).
**Learning:** Even if the file storage relies on cloud objects (like S3) without a traditional filesystem, arbitrary key construction can overwrite unintended objects or escape bounds when local fallbacks (like `fs.writeFileSync`) are used. Prepending unique IDs only fixes naming collisions, not path traversal.
**Prevention:** Always extract the base filename from user uploads using `path.basename()` and further sanitize invalid/unsafe characters (e.g., using regex `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before using the filename in path operations. In addition, validate user-provided directory variables (like `subfolder`) against null bytes and traversal patterns (`..`).

## 2024-06-18 - ISO 19650 Naming Convention & Implicit Sanitization
**Vulnerability:** While `files.service.ts` uses `file.originalname` directly in some local path generations (via `uniqueId`), it is protected by the `NamingConventionService` which strictly validates filenames against the ISO 19650 regex (`^([A-Z0-9]+)-...$`). If an upload method directly utilizes this validation and extracts a derived unique ID, it inherently protects against path traversal by rejecting malicious patterns before they can be used in paths.
**Learning:** Strong upfront business logic validation (like a strict regex match for a naming standard) can inadvertently act as a powerful security control against injection flaws downstream.
**Prevention:** Always sanitize directly at the usage point (e.g., using `path.basename` for unknown files) even if upstream validation exists, to ensure defense in depth and protect against future code refactors that might bypass the upstream validator.
