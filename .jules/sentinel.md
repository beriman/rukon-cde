## 2024-05-24 - Path Traversal in File Uploads
**Vulnerability:** The application was vulnerable to path traversal because `file.originalname` provided by the client was concatenated directly into file paths (via `path.join`) and S3 keys without sanitization in `FilesService` and `SiteCaptureService`. An attacker could use a filename like `../../../etc/passwd` to manipulate the destination of the file write or S3 object.
**Learning:** In Node.js (and frameworks like NestJS using Multer), `file.originalname` is entirely user-controlled and untrusted. The use of `path.join` with an unsanitized relative path from user input overrides the base directory and leads directly to path traversal.
**Prevention:** Always sanitize `file.originalname` using `path.basename(file.originalname)` to strip directory components. For added safety, follow up with regex replacement (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) to remove potentially unsafe characters before using the string in file system or cloud storage operations.
