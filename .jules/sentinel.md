## 2024-07-31 - Path Traversal via Unsanitized `file.originalname`
**Vulnerability:** Path Traversal vulnerability found in multiple services (`FilesService.upload`, `FilesService.uploadSystemFile`, and `SiteCaptureService.create`) because user-provided `file.originalname` was directly appended to path/S3 keys without sanitization. In `uploadSystemFile`, the `subfolder` parameter was also vulnerable.
**Learning:** Prepending a UUID or timestamp to a filename does *not* prevent path traversal if the original filename contains directory separators (`../`) and is evaluated by file system APIs or object storage (which can allow overwriting files elsewhere). Also, relying on a downstream validation service (like `NamingConventionService`) leaves other bypasses open if the primary method fails secure first.
**Prevention:** Always extract the base filename unconditionally using `path.basename(file.originalname)` and sanitize remaining characters (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) at the very beginning of the upload handler before any validation or usage. Ensure explicit rejection of `..` and `\0` in variable directory parameters.
