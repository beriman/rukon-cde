## 2024-05-24 - [Path Traversal via Untrusted Subfolders and Filenames in Uploads]
**Vulnerability:** The `FilesService.uploadSystemFile` method accepted an unsanitized `subfolder` string and `file.originalname` directly into S3 key construction and local filesystem `path.join()`. This allowed path traversal (e.g., `../../../etc/passwd` or `..\..\`) and arbitrary file write capabilities, particularly critical if local fallback is used.
**Learning:** In Node.js, prepending a string (like a timestamp or prefix) to a user-provided filename does *not* prevent path traversal if the original filename contains directory separators and is processed by `path.join()`. Furthermore, when sanitizing user-provided subfolder strings against path traversal, the order of operations is critical: backslashes must be replaced with forward slashes *before* stripping `../` sequences, otherwise attackers can bypass the filter using mixed slashes (e.g., `..\//`).
**Prevention:** Always sanitize raw input like `file.originalname` using `path.basename()` before appending or manipulating it. For dynamic subfolder paths, apply strict multi-step regex replacement (backslashes to forward slashes -> null bytes -> `../` sequences -> leading slashes) or strict whitelisting before utilizing them in file paths or S3 keys.
