## 2025-05-01 - Path Traversal via file.originalname in File Uploads
**Vulnerability:** The `file.originalname` string received from multipart form uploads is completely user-controlled. The `FilesService.uploadSystemFile` and `SiteCaptureService.create` methods were using it directly to construct file paths for local storage and keys for S3 buckets without sanitization. An attacker could specify `../../` or `..\..\` to traverse paths. In addition, `subfolder` string inputs were also used in local file path construction in `FilesService.uploadSystemFile` and were vulnerable to path traversal.
**Learning:** `file.originalname` is never to be trusted, as it may contain malicious path components that can lead to Path Traversal vulnerabilities (CWE-22). Simply replacing slashes via regex must be comprehensive enough to cover both backslash (`\`) and forward slash (`/`). The safest cross-platform method is extracting just the base filename by first replacing any backward/forward slashes with forward slashes and using `path.basename()`.
**Prevention:** Always sanitize user-provided filenames via `path.basename((file.originalname || '').replace(/[\/\\\\]/g, '/'))` or similar logic before concatenating them into a file path or object key. Always validate and sanitize user-provided subfolder names as well.
