## 2024-07-06 - Path Traversal in Object Storage Keys via Unsanitized Input
**Vulnerability:** User-controlled inputs (`file.originalname` and `subfolder` parameters) were used directly to construct S3 object keys and local file paths without proper sanitization. This allows an attacker to perform path traversal using `../` sequences or null bytes to overwrite arbitrary objects or escape intended storage boundaries.
**Learning:** Even though object storage (like S3) does not have a traditional filesystem hierarchy, using directory separators in keys with unsanitized input can still lead to unauthorized object access and overwriting. Node.js `path.join()` does not automatically sanitize directory traversal characters in the input components if the resulting path is considered absolute or traverses outside the base dir.
**Prevention:** Always sanitize `file.originalname` immediately upon handling file uploads (e.g., using `path.basename(file.originalname).replace(/[^a-zA-Z0-9.\-_]/g, '_')`). Explicitly validate any user-provided path components (like `subfolder`) to reject malicious characters such as `..` or `\0`. Reassign the sanitized value back to `file.originalname` to ensure all downstream validation, logging, and metadata extraction use the safe value.
