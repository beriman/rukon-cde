## 2024-05-18 - [Path Traversal via Unsanitized Filenames in Upload Handlers]
**Vulnerability:** User-controlled `file.originalname` in `FilesService.upload`, `FilesService.uploadSystemFile`, and `SiteCaptureService.create` was directly concatenated into filesystem paths and S3 keys without sanitization, leading to path traversal vulnerabilities. A `subfolder` parameter was also vulnerable.
**Learning:** Prepending random data like UUIDs or timestamps to unsanitized filenames does not secure `path.join` calls against directory traversal (`../`). The raw input must always be securely sanitized.
**Prevention:** Always use `path.basename(file.originalname)` combined with a robust regex replacement like `.replace(/[^a-zA-Z0-9.\-_]/g, '_')` to extract a safe filename string *before* using it in filesystem operations or assigning it to object storage keys. Validate variable subfolder strings with simple explicit rejection rules (e.g. `!subfolder.includes('..') && !subfolder.includes('\0')`).
