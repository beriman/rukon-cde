
## 2024-05-20 - Path Traversal via Untrusted Filename and Subfolder Parameters
**Vulnerability:** In `FilesService.uploadSystemFile` and `SiteCaptureService.create`, `file.originalname` and `subfolder` parameters were used directly to construct file paths and S3 keys without sanitization. This allowed attackers to use directory traversal characters (e.g., `../` or null bytes `\0`) to overwrite arbitrary files outside the intended upload directory, leading to a critical path traversal vulnerability.
**Learning:** Even when using object storage (S3) or when raw input seems benign (like `file.originalname`), we must never trust client-provided strings directly in file path construction. The risk applies doubly when a local fallback filesystem is used, as it can lead directly to remote code execution (e.g. overwriting scripts) or data corruption.
**Prevention:** Always explicitly extract the basename using `path.basename()` and further strip unsafe characters using strict regex replacement (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before using filenames. Additionally, validate all directory path components (like `subfolder`) to explicitly reject traversal payloads (`..` and `\0`).
