## 2024-05-16 - [CRITICAL] Fix Auth Bypass & Data Leak in Google Sync
**Vulnerability:** The `/auth/google-sync` endpoint previously trusted unauthenticated client payloads (specifically `email`) to provision and return JWTs. This allowed trivial account takeover for any known user email. Furthermore, a naive patch attempt attempted to unconditionally forward client-provided tokens to Google's `tokeninfo` API, which would have leaked valid local Supabase JWTs to Google servers if submitted.
**Learning:** Never trust the client to assert its identity. Always require and cryptographically verify a trusted authentication token on the server. Furthermore, when integrating with services like Supabase that already normalize OAuth providers, the backend should only trust and verify the Supabase JWT (`access_token`) locally instead of re-verifying external OAuth provider tokens and risking data leakage or brittle dependencies.
**Prevention:** Implement strict local JWT validation logic using the appropriate secret (e.g. `SUPABASE_JWT_SECRET`) instead of trusting unauthenticated client payloads or leaking internal JWTs to external third-party identity verification endpoints.
