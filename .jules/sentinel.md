## 2026-06-08 - [Path Traversal in S3 Key Construction and File Path Creation]
**Vulnerability:** Found multiple instances where `file.originalname` and `subfolder` inputs were directly concatenated into S3 object keys or local file paths in `FilesService.uploadSystemFile` and `SiteCaptureService.create`. This creates a path traversal vulnerability and can also result in arbitrary S3 object overwrites or storage outside the intended boundaries if a malicious filename contains directory separators like `../`.
**Learning:** Even though S3 object storage doesn't strictly have 'directories' like a local filesystem, incorporating an unsanitized `file.originalname` into an S3 key allows an attacker to dictate the final object path, potentially overwriting critical system files or storing files in unauthorized locations. The local filesystem fallback in `uploadSystemFile` is also directly exploitable via both `subfolder` and `file.originalname` inputs, leading to classic path traversal.
**Prevention:** Always sanitize any untrusted input used in file or key paths. Use `path.basename()` to extract just the filename, followed by regex sanitization like `.replace(/[^a-zA-Z0-9.\-_]/g, '_')` to ensure safe characters. When taking path arguments like `subfolder`, validate them strictly (e.g., rejecting `..` and `\0`).
