## 2024-06-20 - Fix Path Traversal in File Uploads
**Vulnerability:** Path traversal and directory traversal vulnerabilities were found in `FilesService.uploadSystemFile` and `SiteCaptureService.create` due to the use of unsanitized `file.originalname` and user-controlled `subfolder` paths. Additionally, `FilesService` used inline `require('fs')` and `require('path')`.
**Learning:** Using untrusted data, specifically the original filename of an uploaded file, to construct a file path or object key can allow attackers to bypass intended directory restrictions (e.g., using `../`). Inline require statements in NestJS are not idiomatic and can cause code review anti-patterns.
**Prevention:** Always sanitize the original filename using `path.basename()` and stripping unsafe characters (e.g., with a regex like `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before using it in path construction. Validate user-controlled path segments (like subfolders) for `..` and `\0` and use ES6 module imports (`import * as path from 'path';`) at the top of the file for core Node.js modules.
