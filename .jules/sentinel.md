## 2025-05-24 - Path Traversal in File Uploads
**Vulnerability:** The application was vulnerable to path traversal attacks during file uploads. Both `files.service.ts` and `site-capture.service.ts` directly used `file.originalname` without sanitization when constructing S3 keys and local file paths. Furthermore, `files.service.ts` accepted a user-provided `subfolder` argument without sanitization. An attacker could craft a filename like `../../../etc/passwd` or provide a malicious subfolder path to overwrite arbitrary files on the local filesystem or escape the intended S3 bucket prefix.
**Learning:** `file.originalname` from multipart form data is completely user-controlled and untrusted. Relying on it directly for file paths or storage keys is a critical security risk. Similarly, user-provided string arguments intended for path construction (like `subfolder`) must be rigorously validated and sanitized.
**Prevention:** Always sanitize `file.originalname` using `path.basename()` to strip any directory traversal sequences. For user-provided path segments (like subfolders), apply strong sanitization, such as stripping backslashes (`\`), directory traversal sequences (`../`), and leading slashes (`/`), or better yet, validate against an allowlist if possible.
