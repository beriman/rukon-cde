## 2026-06-19 - Path Traversal Vulnerability via File Original Name in S3 Keys
**Vulnerability:** User-provided `file.originalname` from multipart/form-data uploads was being concatenated directly into S3 object keys or local file paths in `FilesService` and `SiteCaptureService` without sanitization. If a filename contains directory traversal characters (e.g., `../`), it could allow attackers to write files outside of the intended directory structure or S3 namespace, potentially overwriting critical files or causing data leakage/corruption.
**Learning:** In Node.js, simply prepending strings (such as timestamps or UUIDs) to a user-provided file name does not prevent path traversal if it eventually passes through `path.join()` or relies on implicit S3 path hierarchies.
**Prevention:** Always extract the base file name using `path.basename(file.originalname)` and explicitly replace potentially unsafe characters (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before any concatenation or path construction occurs. Subfolder structures parameterized by the user must also be rigorously validated to reject malicious patterns like `..` or `\0`.
