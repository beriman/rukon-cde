## 2024-05-27 - Path Traversal in File Uploads
**Vulnerability:** Path traversal vulnerability existed in S3 key and local file path generation logic in `files.service.ts` and `site-capture.service.ts`. The `file.originalname` field from the uploaded file was being directly interpolated into the path string, and `subfolder` variable wasn't validated, allowing an attacker to overwrite arbitrary files using `../`.
**Learning:** In Node.js applications handling multipart form uploads, the `file.originalname` provided by the client is completely untrusted and must always be sanitized before being used in S3 keys or file system paths. Even in S3, path traversal can allow attackers to place objects in unintended buckets or prefix directories.
**Prevention:** Always use `path.basename(file.originalname)` to strip directory components from the client-provided name, and strictly validate or replace unsafe characters using regex `/[^a-zA-Z0-9.\-_]/g`. Explicitly validate input fields used for subfolders to ensure they don't contain directory traversal characters like `..` or `\0`.
