## 2024-05-24 - [Path Traversal in S3 Key Construction]
**Vulnerability:** User-controlled filenames (`file.originalname`) and subfolder parameters were used unsanitized in the generation of S3 object keys and local fallback paths (e.g., `FilesService.uploadSystemFile` and `SiteCaptureService.create`), enabling attackers to potentially write files to unintended paths via path traversal (`../` or null bytes) bypassing directory scoping.
**Learning:** Even when generating unique IDs to form paths, including the raw `originalname` unsanitized at the end of the constructed key/path bypasses typical protection when passing variables like directory names/IDs. Reassigning the safe variable back to `file.originalname` early makes down-stream processes naturally safe without extensive refactors.
**Prevention:** Always sanitize unsanitized inputs like `file.originalname` with `path.basename` and regex stripping before use. For explicit path variables like `subfolder`, proactively reject sequences like `..` or null bytes instead of performing complex replacement validation. Ensure imported modules like `path` and `fs` are imported cleanly at the top of the file as ES6 modules.
