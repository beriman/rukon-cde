## 2025-04-14 - Fix Path Traversal in File Uploads
**Vulnerability:** File uploads (e.g., `files.service.ts` and `site-capture.service.ts`) used unsanitized `file.originalname` directly in S3 keys and local file paths. This allowed path traversal (e.g., uploading files with names like `../../etc/passwd`) potentially writing arbitrary files if a local fallback is used, or polluting S3 object structures. The `subfolder` variable was also used directly without validation.
**Learning:** Even though S3 handles keys differently than a POSIX file system, local fallback code exists and concatenates raw file names with base directories. Untrusted user inputs should never be used directly in path construction.
**Prevention:** Always use `path.basename(file.originalname)` to extract just the file name from a user-provided original name. Implement strict regex validation (e.g., `/^[a-zA-Z0-9_-]+$/`) for any directory or subfolder parameters accepted from the user before using them in file paths.
