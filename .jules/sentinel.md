
## 2024-05-31 - Path Traversal Vulnerabilities in File Uploads
**Vulnerability:** Untrusted user input (`file.originalname` and `subfolder`) was used directly in constructing `path.join` and S3 object keys (`s3Key`) in `FilesService.upload` and `FilesService.uploadSystemFile`. This could allow attackers to perform path traversal using `../` or to inject unexpected characters to overwrite other files/objects, even without a local filesystem involved.
**Learning:** In both local storage and cloud storage setups, prepending IDs or timestamps does not protect against directory manipulation if the untrusted filename contains traversal sequences (e.g., `../`). Furthermore, explicitly `require()`ing standard node libraries inline inside conditionals should be avoided in favor of ES6 imports.
**Prevention:** Always sanitize `file.originalname` using `path.basename(file.originalname).replace(/[^a-zA-Z0-9.\-_]/g, '_')` to extract the base name safely and remove unsafe characters. Reassign it back to `file.originalname` before any logic (like validation services, S3 metadata processing, or file path building) uses it. Validate directory parameters (`subfolder`) to ensure they don't contain `..` or `\0`.
