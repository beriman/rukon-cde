## 2024-05-15 - [Path Traversal via Untrusted Original Filenames]
**Vulnerability:** Found multiple instances where the raw user-controlled `file.originalname` string was interpolated directly into S3 object keys and local file paths during uploads (e.g. `SiteCaptureService` and `FilesService`). This allows attackers to perform path traversal using characters like `../` to upload files to arbitrary locations or overwrite existing objects.
**Learning:** Even when using cloud storage like S3, un-sanitized keys derived from untrusted client input can be manipulated to place files in incorrect key hierarchies. The problem is exacerbated if local filesystem fallbacks exist. `subfolder` parameters also present a similar risk.
**Prevention:** Always sanitize client-provided filenames using `path.basename(file.originalname)` before incorporating them into any storage path or S3 key. Additionally, validate user-provided directory paths (like `subfolder`) against directory traversal sequences such as `..` and `\0`.
