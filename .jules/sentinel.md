## 2024-05-24 - [CRITICAL] Multiple API endpoints exposed due to commented out or missing authentication guards
**Vulnerability:** Several controllers within the `apps/api` application, particularly within the `construction`, `classification`, `design`, `loin`, and `simulation` domains, were missing authentication guards completely, or had them commented out out-of-the-box (likely due to boilerplate scaffolding remaining). This left sensitive operations exposed to unauthorized access.
**Learning:** The NestJS default scaffolding may sometimes comment out `@UseGuards` or leave it out if the developer plans to test endpoints locally without auth. It is critical to systematically review all controllers with tools like `grep` to ensure `JwtAuthGuard` is actively applied, rather than relying on assumed default protections.
**Prevention:** Implement a global middleware/guard or lint rule requiring explicitly declaring controllers public or protected. Always verify authentication checks when generating new controllers.
