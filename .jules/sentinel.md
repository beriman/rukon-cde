## 2025-02-18 - [Path Traversal in File Upload and S3 Object Key Construction]
**Vulnerability:** In `apps/api/src/files/files.service.ts` and `apps/api/src/site-capture/site-capture.service.ts`, the `file.originalname` string directly passed from multipart file uploads and the `subfolder` string passed in arguments were concatenated directly into AWS S3 object keys and local `path.join()` structures. This allowed path traversal (Arbitrary File Write) and manipulation of the AWS S3 key tree using special characters (like `../`).
**Learning:** Never trust the `originalname` property from `multer` or similar upload middlewars. NestJS doesn't automatically sanitize it, and AWS S3 doesn't prevent folder traversal characters like `../` from being interpreted in standard key hierarchies. Furthermore, `path.join()` resolves `../` locally, allowing arbitrary file writes.
**Prevention:** Always wrap `file.originalname` with `path.basename()` to drop directory hints, and strongly sanitize any leftover characters with a strict regex (e.g., `replace(/[^a-zA-Z0-9.\-_]/g, '')`). Subfolders provided as generic strings must be strictly validated with regex (e.g., `/^[a-zA-Z0-9_-]+$/`) to prevent nested traversal attacks.
