## 2024-06-27 - [Path Traversal in File Uploads]
**Vulnerability:** Path traversal vulnerability due to unsanitized user-controlled `file.originalname` in `FilesService.upload`, `FilesService.uploadSystemFile`, and `SiteCaptureService.create`. Attackers could use `../` sequences in filenames to write files outside intended directories or manipulate S3 object paths. Additionally, `subfolder` arguments in `uploadSystemFile` were unvalidated.
**Learning:** Even when derived unique IDs are generated for filenames, the raw `file.originalname` must still be sanitized before being mapped to database fields (like `originalName`) or S3 metadata (like `original-name`) to prevent downstream injection. Passing the raw, unsanitized filename to validation or path building methods bypasses security entirely.
**Prevention:** Always extract the base name of a user-provided file using `path.basename()` and strip dangerous characters with a strict regex (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) *before* using the filename in validations, metadata, or path construction. Validate any folder/subfolder path variables by actively rejecting those that contain `..` or `\0`.
