
## 2024-04-30 - Path Traversal Vulnerability in File Upload Handlers
**Vulnerability:** Found a Path Traversal vulnerability in `apps/api/src/files/files.service.ts` (`uploadSystemFile`) and `apps/api/src/site-capture/site-capture.service.ts` (`create`). The `file.originalname` from a file upload (which is user-controlled) and `subfolder` variable was concatenated directly into file paths and S3 keys without any sanitization. This allowed attackers to craft malicious filenames (e.g., `../../../etc/passwd`) or paths to read/write arbitrary files or S3 keys.
**Learning:** Even when the primary storage is S3, failing to sanitize filenames impacts object keys which can overwrite files in other locations, and when falling back to a local filesystem, allows directory traversal leading to arbitrary file write or overwrite. It also teaches that user-controlled inputs in multi-part form data uploads (`originalname`) must never be trusted.
**Prevention:** Always wrap `file.originalname` with `path.basename()` before using it to construct any file paths or object keys. Ensure that parameters used to specify directories or subfolders are strictly validated or sanitized against path traversal characters (like `..` and `/` or `\\`).
