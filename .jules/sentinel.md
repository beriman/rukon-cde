## 2024-10-27 - Path Traversal in File Uploads via Unsanitized `file.originalname`
**Vulnerability:** The application used `file.originalname` directly to construct file paths and S3 keys during file uploads (e.g., `uploadSystemFile` and `SiteCaptureService.create`). Prepending a string like a timestamp or UUID does not prevent path traversal if the original filename contains directory separators (`../`).
**Learning:** Even when prefixing generated IDs, appending untrusted input directly to path components allows malicious users to write files to arbitrary locations. Path traversal must be blocked by sanitizing the actual filename component extracted from the user's input.
**Prevention:** Always extract the base name of a user-provided file using `path.basename()` and strip illegal characters using a regex like `.replace(/[^a-zA-Z0-9.\-_]/g, '_')` before using it to construct any file path or S3 key. Additionally, sanitize any user-provided subfolder paths by removing sequences like `../`, leading slashes, and null bytes.
