## 2024-05-24 - Unsanitized User Input in File/S3 Paths (Path Traversal)
**Vulnerability:** The raw `file.originalname` string from multipart form uploads was being directly concatenated into S3 keys and local file paths (e.g., `uploadSystemFile`, `SiteCaptureService.create`). Prepending a UUID or timestamp to `file.originalname` does not prevent path traversal if the filename contains directory separators.
**Learning:** Even when using randomly generated prefixes or safe directories, if an unsanitized original filename containing `../` is processed by Node.js `path.join()`, it can traverse up the directory structure and write to arbitrary locations. Similarly, in S3, this allows arbitrary key manipulation, potentially bypassing access policies or overwriting unintended objects.
**Prevention:** Always explicitly sanitize user-provided filenames. Extract the base filename using `path.basename()` first to strip any directory separators, and then run a regex replacement (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) to remove any remaining invalid or unsafe characters before using it in storage operations or metadata.
