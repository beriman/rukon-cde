## 2024-06-06 - Path Traversal Vulnerability in File Upload Services
**Vulnerability:** The `FilesService.uploadSystemFile` and `SiteCaptureService.create` methods used unsanitized `file.originalname` in constructing S3 keys and local file paths. `FilesService.uploadSystemFile` also accepted an unsanitized `subfolder` string argument. This allowed attackers to craft malicious payloads (e.g., `../../etc/passwd`) to read or write arbitrary files, leading to a path traversal vulnerability.
**Learning:** Node.js file processing and AWS S3 SDK do not automatically sanitize file paths or object keys. Using raw `file.originalname` or user-controlled directory inputs without explicit sanitation and validation creates critical file injection risks. Prepending an ID or timestamp is insufficient since directory separators in the payload bypass the prefix context.
**Prevention:** Always use `path.basename(file.originalname)` followed by a whitelist regex (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) to strip directory structures and unsafe characters. Validate any user-supplied subfolder paths by actively rejecting input containing `..` or `\0`. Use ES6 module imports for standard library modules like `path` and `fs` at the top level instead of local `require` calls.
