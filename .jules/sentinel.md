## 2025-02-28 - Path Traversal via Unsanitized `file.originalname` in File Uploads
**Vulnerability:** File upload methods in `FilesService.uploadSystemFile` and `SiteCaptureService.create` directly concatenated the untrusted `file.originalname` parameter from user-provided file uploads into server-side file paths and S3 keys. This allowed a malicious user to craft a file upload with a filename like `../../../etc/passwd`, causing path traversal vulnerabilities on the local file system (during fallback) or arbitrary S3 object overwrites.
**Learning:** The `originalname` property from multipart form data (e.g., via Express/Multer) is entirely user-controlled. Even when prefixed with timestamps or UUIDs, the unvalidated inclusion of `/` or `..` sequences allows directory traversal attacks when combined with `path.join()`.
**Prevention:** Always treat `file.originalname` as untrusted user input. Utilize `path.basename(file.originalname)` to extract only the filename component, stripping any directory sequences before using it in file storage operations or S3 key generation.
