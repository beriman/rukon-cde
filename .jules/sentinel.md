## 2024-05-24 - Missing Authentication on Construction Endpoints
**Vulnerability:** Several controllers within `apps/api/src/construction` were completely exposed. Specifically, `ConstructionController`, `SubmittalController` had their `@UseGuards(JwtAuthGuard)` commented out, while `ClaimController` and `ProcurementController` were entirely missing any guard declarations. `CorrespondenceController` used the default `@nestjs/passport` `AuthGuard('jwt')` instead of the project's custom `JwtAuthGuard`. This allowed unauthenticated access to sensitive construction management API endpoints.
**Learning:** During scaffolding or development, it's common to comment out authentication guards to test APIs easily. However, failing to re-enable them before committing code leads to critical security gaps. The project relies on a custom `JwtAuthGuard` that should be used universally across the API to ensure consistency and support for custom decorators like `@Public()`.
**Prevention:** Always verify that all controllers and sensitive endpoints explicitly implement the `@UseGuards(JwtAuthGuard)` decorator. Avoid commenting out security features for testing purposes; instead, use valid mock tokens or configured bypasses in lower environments. Pre-commit hooks or automated PR security checks should verify the presence of authentication guards on all new or modified controllers.
