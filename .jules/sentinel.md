## 2024-06-01 - Path Traversal in File Upload and S3 Keys via Unsanitized Original Filenames
**Vulnerability:** Path traversal vulnerability exists when a backend processes file uploads and directly relies on `file.originalname` to construct local filesystem paths or S3 object keys. S3 key manipulation can result in object overwrite/directory structures being polluted, whereas local system path manipulation can lead to unauthorized directory traversal/writes (e.g. writing to `../../etc/` paths). Furthermore, accepting user-controlled path parameters like `subfolder` without strict validation contributes to the problem.
**Learning:** Appending a random UUID or timestamp prefix to a user-provided filename does NOT make it secure from path traversal if the underlying framework evaluates directory traversal sequences (like `../`). For instance, `/path/to/upload/${timestamp}-../../../etc/passwd` correctly evaluates to `/etc/passwd`. `file.originalname` is fundamentally unvalidated client input and must always be treated suspiciously.
**Prevention:** Always extract only the actual file name using `path.basename()` and further strip out unsafe characters using a regex like `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`. Similarly, any generic path variables derived from input (like `subfolder`) must be validated to strictly deny traversal sequences (e.g. throwing an error if it contains `..` or `\0`).
