## 2024-06-10 - [S3 Path Traversal via Unsanitized Filename and Subfolders]
**Vulnerability:** A path traversal vulnerability existed in file upload services (e.g., `FilesService.uploadSystemFile`). The code concatenated an unsanitized `file.originalname` and user-provided `subfolder` to construct S3 keys and local file paths (e.g., `org-ID/system/${subfolder}/${timestamp}-${file.originalname}`). Even in S3 environments without a local filesystem, directory separators (`../`) in S3 keys can allow an attacker to bypass intended path boundaries and overwrite arbitrary objects within the bucket.
**Learning:** Prepended timestamps or generated IDs are insufficient to stop path traversal if the original filename still contains unsafe directory separator characters, as `path.join()` or generic S3 key string concatenation will process the `../` directives. Additionally, subfolder arguments must be validated.
**Prevention:** Always sanitize untrusted raw filenames using `path.basename(file.originalname)` and explicitly replace unsafe characters (e.g., `replace(/[^a-zA-Z0-9.\-_]/g, '_')`). Furthermore, validate user-provided subfolder names with a strict fail-secure check against directory traversal strings (`..`) and null bytes (`\0`).
