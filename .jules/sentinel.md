## 2025-02-28 - Path Traversal via Unsanitized Original Filename
**Vulnerability:** In `FilesService.uploadSystemFile` and `SiteCaptureService.create`, the `file.originalname` attribute was being concatenated directly into local file paths via `path.join()` or into S3 object keys. Since `file.originalname` is user-controlled, attackers could introduce directory separators (`../` or `\0`) causing path traversal. For S3, this allows attackers to jump out of intended directories and overwrite arbitrary files across the bucket, even without a local filesystem.
**Learning:** Using `path.join` with untrusted inputs dynamically resolves directory traversal sequences. S3 also implicitly resolves directory structures based on keys, making it vulnerable to logical traversal and overwrite attacks when untrusted path delimiters are present.
**Prevention:** Always extract only the filename base using `path.basename()` from any user-uploaded file metadata, and follow up with a regex to remove unsafe characters (e.g., `replace(/[^a-zA-Z0-9.\-_]/g, '_')`) before using the value in any storage operation. Additionally, fail securely by explicitly rejecting (`BadRequestException`) parameters intended to be subfolders if they contain traversal characters like `..` or `\0`.
