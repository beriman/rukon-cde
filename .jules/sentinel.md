## 2024-05-15 - Unsanitized User Input in File Upload Paths (Path Traversal)
**Vulnerability:** The `FilesService.uploadSystemFile` and `SiteCaptureService.create` methods used `file.originalname` directly without sanitization when constructing S3 keys and local file system paths (e.g., `const filePath = path.join(uploadDir, ${timestamp}-${file.originalname})`). An attacker could supply a malicious filename like `../../../etc/passwd` to overwrite arbitrary files on the local filesystem if the S3 fallback is active, or manipulate S3 object keys.
**Learning:** Even though primary uploads (`FilesService.upload`) validate against the strict ISO 19650 standard (which inherently prevents path traversal), utility or background upload methods (`uploadSystemFile`, `SiteCaptureService`) often bypass this strict validation. Developers falsely assumed `file.originalname` is safe or "just a string," forgetting that it is directly controlled by the user.
**Prevention:** Treat all `file.originalname` properties from multipart form uploads as untrusted user input. Always extract just the final filename segment using `path.basename(file.originalname)` and follow up with a strict regex replacement (e.g., `.replace(/[^a-zA-Z0-9.\-_]/g, '_')`) to strip any remaining potentially unsafe characters before concatenating them into file paths or storage keys.
