## 2024-12-07 - [Path Traversal in File Uploads]
**Vulnerability:** The application used `file.originalname` and user-provided `subfolder` strings directly when constructing S3 keys and local file paths in `SiteCaptureService.create` and `FilesService.uploadSystemFile`. This allowed path traversal vulnerabilities where an attacker could upload files to unintended directories (e.g. `../../../../etc/passwd`).
**Learning:** Even when falling back to cloud storage (like S3) where standard OS path traversal might not have the same system-level impact, constructing keys with unvalidated input can overwrite unintended objects. For local disk fallbacks, it presents a critical file-write vulnerability. `path.join` natively resolves `../`, meaning prepending a UUID or timestamp does not protect against a malicious `originalname`.
**Prevention:** Always extract the base filename using `path.basename()`, apply a strict whitelist regex replacement for allowed characters (e.g., `/[^a-zA-Z0-9.\-_]/g`), and strictly validate directory arguments by rejecting paths containing `..` or `\0`.
