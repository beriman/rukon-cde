## 2024-05-15 - Unauthenticated Account Takeover via OAuth Sync Bypass
**Vulnerability:** The `/auth/google-sync` endpoint trusted client-provided user metadata (`email` and `name`) without any server-side token validation. This allowed an attacker to completely bypass authentication and gain full access to any user account simply by sending an unauthenticated POST request containing the target user's email address.
**Learning:** This architectural flaw occurred because the frontend successfully authenticated the user via Supabase, but the backend completely ignored the frontend session and simply trusted the payload data blindly. This breaks the fundamental security principle of never trusting the client.
**Prevention:** Always ensure that client-provided user identity properties (like `email`) are backed by server-side verification using an external identity provider token (such as Google OAuth's `tokeninfo` endpoint) before assigning access privileges or assuming the identity of the user. Ensure token audience (`aud`) checks are implemented to prevent Confused Deputy attacks.
