## 2024-05-24 - Path Traversal in File Uploads via Prepending Prefix
**Vulnerability:** Constructing S3 object keys or local file paths by prepending a unique ID or timestamp to `file.originalname` without sanitization. An attacker can use traversal payloads (e.g. `../../../etc/passwd` or `../.ssh/authorized_keys`) in the filename to bypass the prefix logic and overwrite arbitrary S3 keys or write to arbitrary locations in the local filesystem fallback.
**Learning:** Prepending a UUID or timestamp to a user-provided string does NOT secure the file path if the untrusted payload contains directory separators (e.g., `/`, `\`) or traversal characters (`..`). The path construction functions (e.g., `path.join`) will resolve the traversal, and S3 will just parse the literal string which can bypass prefix restrictions.
**Prevention:** Always explicitly sanitize `file.originalname` using `path.basename()` followed by a regex replace to remove unexpected characters (e.g., `/[^a-zA-Z0-9.\-_]/g`) *before* generating keys or combining paths. Furthermore, validating structural subfolder arguments (e.g. throwing error if they contain `..` or `\0`) provides defense-in-depth.
